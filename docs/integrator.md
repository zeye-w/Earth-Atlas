## 审查清单

自动检查（GitHub Actions）会跑：类型检查、单元测试（含数据文件校验）、构建、全部浏览器测试（CI 里约 16 分钟），以及热点文件守卫 `ownership`。**这些全绿只说明代码没坏，不说明可以合并。** 你还要看：

1. **诚实**：每个点、每条线都要能说明是实测、推算还是示意，图层说明和信息卡要写清楚。数据缺失时要显示"暂不可用"，不能补假数据。反例：把 OSM 光缆片段的端点当成"登陆站"发布（PR #16 出现过，已修）。
2. **许可**：只发布许可明确允许再分发的数据（见协作文档"数据源"一节）；署名要出现在页面底部的署名行和面板里。
3. **文件归属**：Codex 不改热点文件（`.github/hotspots.txt`）。如果确实需要改，由你来改；或者确认合理后给 PR 加标签 `hotspots-approved`。
4. **看实际效果**：动到渲染或数据的 PR，用真实数据截图看一眼（方法见下）。测试用的是合成数据，看不出真实数据量下的问题。
5. **不跳过测试**：不允许删除或跳过测试来让检查变绿。

处理结果：
- **合并**：用 merge commit（不要 squash 或 rebase 别人的提交）。合并前确认 PR 已经合过最新的 `main`，并在本地跑过 `npm test`。
- **小问题**：在 PR 评论里列出来，让作者改；或者合并后由你提交一个小修补（PR #16 就是这样处理的），并在 PR 评论里说明改了什么。
- **大问题**：退回，在评论里写清楚原因和期望的改法。

GitHub 上的每条评论末尾要附上：

```

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## 环境和工具（Claude Code 云端容器）

- **容器连不上外网**：CelesTrak、OSM、RIPE Atlas 等都访问不了，只能访问 GitHub 和 npm。需要真实数据时：静态数据已经提交在 `public/data/internet/`；在线数据要靠 GitHub Actions 或 Codex。
- **GitHub 操作**：用 `mcp__github__*` 工具（先用 ToolSearch 加载），例如 `pull_request_read`（get、get_diff、get_check_runs、get_files）、`merge_pull_request`、`add_issue_comment`、`get_job_logs`。没有 `gh` 命令。
- **本地检查命令**：
  - `npm run typecheck`、`npm test`、`npm run build`
  - 浏览器测试：`PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test tests/e2e/internet.spec.ts`（单个文件约 1 分钟；全部约 16 分钟，适合放到后台跑）。不要运行 `playwright install`。
- **用真实数据截图**：浏览器测试默认用合成数据替换 `/data/internet/*`。临时写一个测试，在 `mockNetwork(page)` 之后加 `await page.route("**/data/internet/**", (route) => route.continue())`，先 `npm run build`，再打开带图层参数的 `sceneUrl(...)` 截图。临时文件放在 `tests/e2e/tmp/`，用完删掉，不要提交。

- **分支保护暂未开启**：有三个定时任务（`internet-data.yml`、`volcano-data.yml`、`screenshots.yml`）会直接推送到 `main`，开启"必须走 PR"会让它们失败。以后把它们改成自动开 PR 后，再开启分支保护：要求 `validate`、`e2e`、`ownership` 通过，并启用 auto-merge。在那之前，"只有集成对话合并到 main"是靠约定执行的。
