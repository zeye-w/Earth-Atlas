## 审查清单

自动检查（GitHub Actions）会跑：`validate`（类型检查、单元测试含数据文件校验、构建）、浏览器测试 `e2e`（拆成 4 份并行跑），以及热点文件守卫 `ownership`。**这些全绿只说明代码没坏，不说明可以合并。** 你还要看：

1. **诚实**：每个点、每条线都要能说明是实测、推算还是示意，图层说明和信息卡要写清楚。数据缺失时要显示"暂不可用"，不能补假数据。反例：把 OSM 光缆片段的端点当成"登陆站"发布（PR #16 出现过，已修）。
2. **许可**：只发布许可明确允许再分发的数据（见协作文档"数据源"一节）；署名要出现在页面底部的署名行和面板里。
3. **文件归属**：Codex 不改热点文件（`.github/hotspots.txt`）。如果确实需要改，由你来改；或者确认合理后给 PR 加标签 `hotspots-approved`。
4. **看实际效果**：动到渲染或数据的 PR，用真实数据截图看一眼（方法见下）。测试用的是合成数据，看不出真实数据量下的问题。
5. **不跳过测试**：不允许删除或跳过测试来让检查变绿。

处理结果：
- **合并**：用 merge commit（不要 squash 或 rebase 别人的提交）。合并前确认 PR 已经合过最新的 `main`，并在本地跑过 `npm test`。何时可以合并见下一节。
- **小问题**：在 PR 评论里列出来，让作者推到**同一个 PR 的分支**上改；或者由你直接推到那个分支上（见下一节）。不要为小修补另开 PR。
- **大问题**：退回，在评论里写清楚原因和期望的改法。

GitHub 上的每条评论末尾要附上：

```

---
_Generated by [Claude Code](https://claude.ai/code)_
```

## 合并节奏（为了提速）

以前慢，主要是三件事叠在一起：每个 PR 都等 20 多分钟的浏览器测试；小修补各自另开 PR，又各等一轮；PR 之间串行，一个卡住后面都在等。现在按下面的规则走：

1. **不等浏览器测试。** `validate` 和 `ownership` 通过（再加上上面的人工检查）就可以合并，不用等 `e2e` 变绿。`e2e` 会在合并后的 `main` 上再跑一次。
   - `main` 上的 `e2e` 失败了，由你**立即处理**：能马上修的，开 `claude/integrator-*` 分支修好合并；修不了的，找出是哪个 PR 引起的，回退那次合并（`git revert -m 1`），并在原 PR 评论里说明。修好之前不合并新的渲染或界面改动。
   - 例外：大改渲染、大改界面、或者改了 `tests/e2e/` 的 PR，还是等 `e2e` 通过再合并。
2. **小修补推到原 PR，不另开。** 审查发现的小问题、作者自己的追加修改，都推到同一个 PR 的分支上。只有原 PR 已经合并或关闭时，才开新 PR。你自己顺手的修补，可以直接推到作者的分支上（在 PR 评论里说明改了什么），不要改写作者已经推送的提交历史。
3. **小修补你可以自己合并，不用问用户。** 条件是同时满足：
   - 不改热点文件（`.github/hotspots.txt` 里列的）；
   - 是修补或小改动，不是新功能、新图层、新数据源；
   - 上面的审查清单都过了。

   **仍然要先问用户**的：改了热点文件的 PR、新功能或大改动、改协作规则的 PR（包括本文档和 `docs/internet-layers.md`）、需要 squash 等例外处理的合并、以及回退别人的大改动。问的时候把 PR 链接、改了什么、你的建议写清楚，一条消息就能决定。
4. **并行审查。** 互不依赖的 PR 可以同时审查、谁先好谁先合，不必排队。

## 环境和工具（Claude Code 云端容器）

- **容器连不上外网**：CelesTrak、OSM、RIPE Atlas 等都访问不了，只能访问 GitHub 和 npm。需要真实数据时：静态数据已经提交在 `public/data/internet/`；在线数据要靠 GitHub Actions 或 Codex。
- **GitHub 操作**：用 `mcp__github__*` 工具（先用 ToolSearch 加载），例如 `pull_request_read`（get、get_diff、get_check_runs、get_files）、`merge_pull_request`、`add_issue_comment`、`get_job_logs`。没有 `gh` 命令。
- **本地检查命令**：
  - `npm run typecheck`、`npm test`、`npm run build`
  - 浏览器测试：`PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test tests/e2e/internet.spec.ts`（单个文件约 1 分钟；全部约 16 分钟，适合放到后台跑。也可以只跑一份：`npx playwright test --shard=1/4`）。不要运行 `playwright install`。
- **用真实数据截图**：浏览器测试默认用合成数据替换 `/data/internet/*`。临时写一个测试，在 `mockNetwork(page)` 之后加 `await page.route("**/data/internet/**", (route) => route.continue())`，先 `npm run build`，再打开带图层参数的 `sceneUrl(...)` 截图。临时文件放在 `tests/e2e/tmp/`，用完删掉，不要提交。
