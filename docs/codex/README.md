# Codex 任务书：格式和规则

给 Codex 派活用的任务书都按这份写。目的是让 Codex 少读、少跑、少等，把 token 花在改代码上。
同目录下 `internet-data.md`、`dns-flows.md` 是早期的长任务书，只作历史参考，不要照着写。

## 写任务书的人（Claude）要遵守

1. **依赖合并后再发。** 任务书里不写"等 #N 合并再开工"之类的等待条件，也不让 Codex 自己查 PR 状态。依赖的 PR 合并了，用户再把任务书发给 Codex。
2. **只写要改的文件、验收标准和热点限制。** 不要求 Codex 通读协作文档或其他背景文档。确实需要的背景，给到具体文件或章节的链接，写一句为什么要看。
3. **不重复协作文档里的通用约定**（坐标格式、许可原则、合并方式等）。只写这次任务会碰到的那一条，或者给链接。
4. **截图只在需要时要求。** 任务书没写，就不截图。
5. **长度控制在一屏左右**（约 40 行以内）。写不下，通常说明该拆成两个任务。

## Codex 要遵守（任务书里不用重复，下面的模板已带一句）

- **本地只跑**：`npm run typecheck`，以及和改动相关的单元测试，例如 `node --experimental-strip-types --test tests/dnsFlows.test.mjs`。
- **不在本地跑**全部单元测试、`npm run build`、浏览器测试（Playwright e2e）。这些交给 CI；CI 红了，只在本地复现失败的那一项。
- 命令输出只看结尾和报错（例如 `| tail -n 40`），不要把整段日志读进来。
- 不轮询、不设定时任务等 PR 或 CI 状态。开完 PR 就结束。
- 不改热点文件（`.github/hotspots.txt`），不新增 npm 依赖，不跳过或删除测试。

## 模板

````markdown
# Codex 任务 · <线>：<一句话标题>

仓库 zeye-w/Earth-Atlas。从最新 `main` 拉分支 `codex/<名字>`，完成后开 PR 到 `main`。

## 目标
<两三句：要做成什么样，为什么。>

## 要改的文件
- `path/to/a.ts`：<改什么>
- `tests/xxx.test.mjs`：<测什么>

## 验收
- <可检查的结果 1>
- <可检查的结果 2>
- 本地：`npm run typecheck` 和 `node --experimental-strip-types --test tests/xxx.test.mjs` 通过。全量测试、构建、e2e 交给 CI。

## 限制
- 只改上面列出的文件。热点文件（`.github/hotspots.txt`）不改，需要改就在 PR 描述里提。
- 不新增依赖，不跳过测试。
- <这次特有的限制，例如"拿不到依据就不匹配，不臆造"。>

## 参考（需要时再看）
- [<文件或章节>](<链接>)：<一句话说明看什么>

## PR 描述
做了什么、跑了哪些命令和结果、已知问题。<需要额外写的内容，例如匹配率。>
````

截图、真实数据核对、许可核实之类的额外要求，只在这次任务确实需要时写进"验收"。
